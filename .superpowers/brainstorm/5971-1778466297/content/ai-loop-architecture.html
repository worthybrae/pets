AI Loop Architecture: Multi-Model Pipeline

How should the pet's creative mind be structured?

A

The Studio Model

Specialized models for each role in a pipeline:

① Dreamer (Claude) — "What should I build next?" Reads memories, conversations, current world state. Outputs a creative brief.
② Architect (Claude/o3) — Takes the brief → produces a detailed build plan with coordinates, materials, phases.
③ Builder (GPT-4o/code model) — Executes the plan. Generates voxel code, places blocks, runs procedural generation.
④ Critic (Claude) — Reviews the build. "Does this match the brief? Is it beautiful? What should change?" Feeds back into the loop.

Pros

  • Each model focuses on what it's best at
  • Critic creates the missing feedback loop
  • Creative output quality goes way up

Cons

  • More API calls = higher cost per tick
  • More complex orchestration
  • Latency between steps
B

The Director Model

One smart model plans, cheap models execute:

① Director (Claude Opus) — Maintains the world vision document. Decides what to build, why, and how. Writes detailed specs.
② Crew (Haiku/GPT-4o-mini) — Executes specs mechanically. Place these voxels here. Run this code. No creative decisions.
③ Director reviews — Same smart model evaluates results, updates the vision, plans next session.

Pros

  • Cheaper — expensive model only used for thinking
  • Simpler pipeline (2 roles not 4)
  • Strong coherence from single creative mind

Cons

  • Less creative diversity
  • Director bottleneck — one model's taste defines everything
  • Review step might be shallow
C

The Ensemble Model

Multiple models "brainstorm" together, best idea wins:

① Pitch — 3 different models each propose what to build next (given same context). Three different creative visions.
② Judge (Claude) — Evaluates pitches against pet personality, world coherence, user interests. Picks the best one + synthesizes.
③ Execute — Winning model builds its vision.
④ Reflect — Judge reviews the result, saves learnings.

Pros

  • Maximum creative diversity
  • Natural selection for quality
  • Surprising, varied output

Cons

  • 3x cost for ideation phase
  • Most complex to orchestrate
  • Risk of incoherent world if judge isn't strong enough

The Missing Piece in All Three: World Memory

Regardless of which model architecture you pick, the pet needs a persistent world document — a living map of what it's built, where, and why. Think of it as the pet's "journal" that any model in the pipeline can read. Without this, no architecture can produce coherence.
